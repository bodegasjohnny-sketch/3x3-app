# 3x3 · Reel Studio (test build)

Front end for Johnny Bodegas's video-automation app. **Static, simulated, noindex.** Live at https://3x3.johnnybodegas.com (GitHub Pages; fallback https://bodegasjohnny-sketch.github.io/3x3-app/).

> TEST MODE: no real jobs, keys or posts. All data lives in this browser's localStorage. Use **Clear data** in the top banner to wipe it.

## Features
- **Intake (9 steps)** built from the approved mockup and the real research data (`js/data.js`, generated by `tools/build_data.py` from `/workspace/video-app-pack`): goal › niche/sub-niche › format & duration › style › voice › brand › captions & audio › safety & platforms › review & lock. Every change autosaves.
  - Goal step: a preset for each goal, plus monetization warnings (TikTok Rewards needs videos over 1 min; mass-produced, templated videos get demonetized; YPP thresholds).
  - Voiceover can be turned off. When it's off, ElevenLabs isn't required.
  - Brand step: live 9:16 preview with the 250px top / 400px bottom safe zones and a WCAG contrast check. White text on the highlight colour is blocked, and pill text automatically switches to dark.
  - Affiliate goal: a disclosure line is inserted automatically into the caption previews, end card, rules and final output.
  - Step 8: **mandatory AI disclosure**, mapped per platform (YouTube "Altered or synthetic content", Meta "AI info", TikTok "AI-generated content"). It can't be skipped, the on-screen tag is locked on for photoreal styles, and Continue/Lock are blocked until it's acknowledged. No-claims rules are always on for health, finance and crypto. The disclaimer is locked on for high-risk niches (health, finance, crypto, kids). Made-for-kids toggle.
  - **Forced rule bundles** (from `taxonomy.json` `rule_bundles`: health, finance, crypto, kids) lock their toggles: the disclaimer (NFA for finance/crypto), no-claims rules, the bundle's banned words (they can't be removed), and made-for-kids with YouTube-only publishing (kids). The crypto bundle blocks the affiliate, e-commerce and digital-product goals; Lock is disabled with an explanation.
  - Review: every missing connection links straight to its fix, a per-video cost estimate (labelled as an estimate), a compiled rules JSON preview, export/import of the intake as JSON, and a required **compliance check** before Lock.
  - Locking creates **intake v1 (read-only)**. "Edit as v2" starts a new version; earlier versions stay viewable and can't be changed.
- **Projects / Project page**: pipeline Rules › Script › Voiceover › Stills › Video › Final stitch › Publish. Status chips: Not started / Running / Needs you / Awaiting approval / Done, plus Failed (with Retry) and Re-approval needed.
  - **Hash-locked approvals**: each stage stores the hash of its inputs (the rules hash plus upstream output hashes), and each approval stores input + output hashes. Swapping a still or regenerating anything upstream voids the approvals after it ("Re-approval needed"); those stages must be regenerated before continuing.
  - Swap any single still; Download (gives you a manifest JSON for now); Queue for publish (needs the platform connections).
  - Test tools: make the next job fail, 3× speed, reset the simulation, delete the project.
- **Connections**: Grok Bot worker (webhook URL + secret), Grok Imagine (route: xAI API, recommended at volume, or SuperGrok browser for low volume, with ToS and rate-limit notes), ElevenLabs, YouTube, Facebook Page, TikTok, Instagram (optional), Google Drive (optional). Each card shows what it's for, which steps use it, and its status (Connected / Missing / Needs re-login / Needs you), plus Connect. Required-but-missing connections are flagged, with a badge count on the nav tab.
- **Onboarding**: a 6-step guide with a progress bar tied to Connections status, an honest explanation of the browser-login flow, and a "Run test job" button.
- Accessibility: keyboard-reachable switches (role=switch, aria-checked), aria-pressed on choice cards, labels on every input, visible focus rings, prefers-reduced-motion, `--dim` text raised to ≥4.5:1. Responsive down to 390px.

## What is simulated vs real
| Real | Simulated |
|---|---|
| Intake logic, research taxonomy/styles, rules compilation, requirement and warning computation, hashing, versioning, localStorage persistence, JSON export/import | All jobs. `js/simulator.js` stands in for the user's Grok Bot worker: script/stills/clips/final are placeholders. Connect/login confirmation ("Simulate: bot confirmed login"). Download returns a manifest instead of an MP4. Publishing never posts anything. |

**Secrets:** key fields accept only placeholders that match `test_…`. Anything that looks like a real key (`sk_…`, long tokens, etc.) is rejected and never stored. Only a masked hint is saved. There are no analytics and no external requests.

## Architecture / swap points
- `js/adapter.js`: **the data adapter (swap point)**. `LocalAdapter` uses localStorage today. Implement `SupabaseAdapter` with the same interface: `projects` and `jobs` tables, Realtime for `subscribe()`, and an Edge Function that signs jobs server-side (HMAC-SHA256 + timestamp + nonce) and POSTs them to the user's worker webhook. Secrets stay in each user's Grok Bot secret store. The schema is in the file header.
- `js/simulator.js`: local fake worker; delete it when going live.
- `js/model.js`: connections, stages, requirements/warnings, secret guard, hashing, AI-disclosure map.
- `js/intake.js`: the intake (from the mockup). `js/pipeline.js`: stage/job state machine. `js/pages.js`: Projects, Project, Connections, Onboarding. `js/app.js`: shell/router.
- Style IDs follow `styles.json` (`vox_collage` was renamed `editorial_collage`; old drafts are migrated through `renamed_ids`). Studio and brand names are kept out of style names and prompts.
- `tools/shoot.py`: Playwright end-to-end click-through plus screenshots (`shots/`).

## Known gaps
- No backend, no auth, no real worker. State is per-browser.
- The 3x3 bot template link isn't public yet (it's a placeholder in Onboarding).
- Logo/frame-overlay upload and "Custom style from reference images" are visual placeholders from the mockup. Voice previews are example data with no audio.
- Script and still content are placeholders. The cost estimate uses unit counts only (no live pricing).
- The "Write my own topic" field isn't validated against banned words yet.
